# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| 1.0.x   | ✅ Yes    |

## Reporting a Vulnerability

**Please do NOT open a public issue for security vulnerabilities.**

Instead, email **xyaz@gmail.com** with:

1. Description of the vulnerability
2. Steps to reproduce
3. Potential impact
4. Suggested fix (if any)

We will acknowledge receipt within 48 hours and provide a timeline for fix.

## Scope

This policy covers:

- The m4ster-tracker frontend application
- CI/CD pipeline configuration
- Docker image build process
- Dependencies (via dependabot alerts)

## Disclosure Timeline

1. **Day 0**: Report received
2. **Day 1-2**: Acknowledgment + initial assessment
3. **Day 7**: Status update (confirmed/investigating/won't fix)
4. **Day 30**: Target fix release (may vary by severity)
5. **Day 30+**: Public disclosure after fix released

## Safe Harbor

We consider good-faith security research authorized when you:

- Make a good faith effort to avoid privacy violations, data destruction, service interruption
- Only interact with your own test accounts/data
- Report findings promptly
- Give us reasonable time to fix before disclosure

We will not pursue legal action against researchers following this policy.
